================================================================================
  1. PROJECT OVERVIEW
================================================================================

PollApp is a full-stack organisational polling platform. Administrators create
and manage polls through a Clerk-authenticated admin panel. Members of the
public vote using only their name and phone number — no account required.

Core user flows:
  • Visitor arrives at the landing page and sees an intro with CTAs.
  • Visitor navigates to /vote to browse all currently open polls.
  • Visitor selects a poll and submits their name, phone number, and
    chosen option(s). No sign-up is needed.
  • The system enforces one vote per phone number per poll (and also
    one vote per name per poll), returning a clear error on duplicates.
  • After voting, the voter sees a confirmation screen.
  • Admin signs in at /sign-in with Clerk credentials.
  • Admin is redirected to /admin and can create, view, edit, and delete
    polls, review individual voter records, see analytics charts,
    and export results as a PDF.
  • Admin can customise the global site theme from /admin/settings,
    choosing one of five preset themes and toggling light/dark mode.
    Changes apply site-wide instantly.

================================================================================
  3. ARCHITECTURE OVERVIEW
================================================================================

  Rendering strategy
  ──────────────────
  All pages are React Server Components (RSC) by default. Data is fetched
  directly in the page via async server actions. Client components ("use client")
  are used only where interactivity is needed (forms, charts, hooks).

  RSC / Client boundary rule
  ──────────────────────────
  React serialisation requires that only plain objects cross the server →
  client boundary. Lucide icon components (functions) cannot be passed as
  props from a Server Component to a Client Component. The Sidebar component
  therefore defines its nav items (including icons) internally, keyed by a
  plain string `variant` prop. AppShell passes `sidebar="admin"` — a plain
  string — to the Sidebar.

  Route groups
  ────────────
  app/
  ├── (auth)/          Public auth pages — no layout wrapper.
  │                    Only /sign-in remains; /sign-up was removed.
  ├── (admin)/         Admin-only pages — wrapped in AppShell with the
  │                    "admin" sidebar variant. Layout checks
  │                    Clerk publicMetadata.role === "admin" and
  │                    redirects non-admins to /.
  ├── api/             API route handlers
  ├── vote/            Public voting pages — SiteHeader only, no sidebar
  ├── page.tsx         Landing page — SiteHeader only
  └── layout.tsx       Root layout — ClerkProvider, RTL detection,
                       data-theme attribute, dark class, font loading.
                       NOTE: (protected)/ was deleted in the rewrite.

  Data flow
  ─────────
  1. Server component calls a server action (actions/*.actions.ts).
  2. Server action connects to MongoDB, queries/mutates, and returns
     ActionResult<T> = { success: true, data: T }
                     | { success: false, error: string, fieldErrors? }.
  3. Server component passes serialised data as props to client components.
  4. Client components call server actions via useTransition (no usePollVote /
     useOptimistic — those were removed in the rewrite).

  Single source of truth for URLs
  ────────────────────────────────
  lib/config/routes.ts exports a `routes` const used everywhere to avoid
  hardcoding URL strings:
    routes.home                       "/"
    routes.vote.list                  "/vote"
    routes.vote.poll(id)              "/vote/[id]"
    routes.admin.dashboard            "/admin"
    routes.admin.polls                "/admin/polls"
    routes.admin.pollNew              "/admin/polls/new"
    routes.admin.pollDetail(id)       "/admin/polls/[id]"
    routes.admin.pollEdit(id)         "/admin/polls/[id]/edit"
    routes.admin.settings             "/admin/settings"
    routes.auth.signIn                "/sign-in"

  Middleware (proxy.ts)
  ──────────────────────
  Clerk middleware protects ONLY:
    /admin(.*)
  All other routes (including /vote and /vote/[pollId]) are fully public.
  Unauthenticated access to /admin/* redirects to /sign-in.
  NOTE: File is named proxy.ts (Next.js 16 convention; middleware.ts
  is deprecated). Build output shows "ƒ Proxy (Middleware)".

  5.03  VOTE ON POLL
  URL:    /vote/[pollId]
  Files:  app/vote/[pollId]/page.tsx (server)
          app/vote/[pollId]/VotePageClient.tsx (client)
  Access: Public
────────────────────────────────────────────────────────────────────────────────

PURPOSE
  Dedicated voting page for a single poll. Voters enter their name and
  phone number, select option(s), and submit. No account is required.

LAYOUT
  SiteHeader → Centred card (max-width xl) → VotePageClient

STATES (managed in VotePageClient)

  Poll open — not yet voted
    • VoterInfoForm: "Your Name" text input + "Phone Number" tel input
      (dir="ltr" for phone regardless of page direction).
    • OptionSelector: list of option cards. Single-select by default;
      multi-select if poll.allowMultipleVotes is true.
    • VoteSubmit button: "Submit Vote". Shows spinner while pending.
    • Error message shown inline if submission fails.

  Poll open — after successful vote
    • VoteConfirmation card: thank-you message, voter name, selected
      option(s), poll title.

  Poll closed or expired
    • Alert with appropriate message — form is not shown.

SERVER DATA FETCHED
  getPollById(pollId)   — full poll document; notFound() if missing

CLIENT DATA / HOOKS
  useVote({ castVoteAction })   — dependency-injected hook that wraps
    the castVote server action in useTransition. Returns:
    { submit, isPending, error, fieldErrors, isSubmitted }

VOTING UNIQUENESS RULES
  One vote per phone number per poll (unique compound index).
  One vote per name per poll (unique compound index).
  Attempting to vote twice returns a specific error message:
    "This phone number has already voted on this poll"
    "This name has already voted on this poll"

COMPONENTS USED
  SiteHeader, VoterInfoForm, OptionSelector, VoteSubmit, VoteConfirmation,
  Alert, AlertDescription

SERVER ACTIONS (called from client)
  castVote(input)   — validates, checks duplicates, inserts Vote document,
                      increments poll.totalVotes, revalidates cache.

    1. Vercel        — clean monochrome black/white palette

    3. Modern Minimal— subtle blue-grey palette, tight radius (0.375rem)

  • Success / error Alert shown after save.

SERVER DATA FETCHED
  getSiteTheme()   — current { themeName, mode } from SiteSettings.
  Falls back to { themeName: "vercel", mode: "light" } if unset or

  updateSiteTheme({ themeName, mode })   — upserts SiteSettings in MongoDB,

COMPONENTS USED

────────────────────────────────────────────────────────────────────────────────
  6.01  CLERK WEBHOOK
  URL:    /api/webhooks/clerk
  File:   app/api/webhooks/clerk/route.ts
  Method: POST
────────────────────────────────────────────────────────────────────────────────

PURPOSE
  Receives lifecycle events from Clerk and keeps the MongoDB User
  collection in sync with Clerk's user store (for admin accounts).

VERIFICATION
  Uses the svix library to verify the webhook signature using
  CLERK_WEBHOOK_SECRET. Returns HTTP 400 if headers are missing or
  the signature is invalid.

HANDLED EVENTS
  user.created   → syncUser() upserts a User document in MongoDB
  user.updated   → syncUser() updates the existing MongoDB document
  user.deleted   → deleteUserByClerkId() removes the User document

RESPONSE
  HTTP 200 "OK" on success.
  HTTP 400 with an error message on verification failure.

REQUIRED ENV VAR
  CLERK_WEBHOOK_SECRET   — obtained from the Clerk dashboard.

  10. AUTHENTICATION & AUTHORIZATION
================================================================================

  Authentication (who you are)
  ──────────────────────────────
  VOTERS do NOT authenticate. They identify themselves with a name and
  phone number when casting a vote.

  ADMINS authenticate via Clerk. The app never stores passwords.

  Session check in server components (admin actions):
    const { userId } = await auth();   // null if unauthenticated

  Session check in middleware:
    await auth.protect();   // redirects to /sign-in if unauthenticated

  Sign-in flow:
    1. Admin visits /sign-in (or is redirected there from /admin).
    2. Clerk <SignIn /> component handles authentication.
    3. On success, redirected to /admin (NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL).
    4. Sign-up link hidden — no public registration.

  User sync:
    When an admin account is created or updated in Clerk, the webhook
    (§ 6.01) fires and calls syncUser() to keep MongoDB in sync.

  Authorization (what you can do)
  ─────────────────────────────────
  Role            How set                       What's unlocked
  ─────────────── ───────────────────────────── ─────────────────────────────
  Public visitor  No account needed             /vote, /vote/[pollId], /
  Admin           Clerk publicMetadata           /admin/* routes, all CRUD
                  { "role": "admin" }            on polls, analytics,
                                                 theme settings

  To grant admin role:
    1. Open Clerk dashboard → Users → select user.
    2. Edit "Public Metadata" → set { "role": "admin" }.
    3. Verify the admin layout guard redirects non-admins correctly.

  11. THEME SYSTEM
================================================================================

  Storage
  ───────
  SiteSettings document (singleton) stores:
    { theme: { themeName: string, mode: "light" | "dark" } }

  CSS definition (globals.css)
  ─────────────────────────────
  Each theme is defined as a CSS attribute selector block:

    [data-theme="vercel"] { ... }       ← light mode variables
    [data-theme="vercel"].dark { ... }  ← dark mode overrides

  Themes covered: vercel, violet-bloom, modern-minimal, nature,
  pastel-dreams. All 30+ shadcn/ui CSS custom properties are defined
  (background, foreground, card, primary, secondary, muted, accent,
  destructive, border, input, ring, radius, chart-1..5, and all
  sidebar-* variables). Values are in the oklch colour space.

  Application (app/layout.tsx)
  ─────────────────────────────
  getSiteTheme() runs on every request. The result is applied to <html>:
    <html data-theme={themeName} className={isDark ? "dark" : ""}>

  Tailwind picks up the correct variable values because the @theme inline
  block maps --color-primary → var(--primary) etc., and the active
  [data-theme] block provides the values for those CSS properties.

  Live preview in ThemeEditor
  ────────────────────────────
  When the admin selects a theme card or toggles mode, the client
  immediately applies:
    document.documentElement.dataset.theme = selectedTheme
    document.documentElement.classList.toggle("dark", mode === "dark")
  This re-themes the entire admin UI in real time without a page reload.
  Saving to MongoDB + revalidatePath propagates the selection to all
  public pages.

  Dark mode
  ──────────
  Activated by the "dark" class on <html>.
  @custom-variant dark (&:is(.dark *)) in globals.css handles all
  Tailwind dark: variants.

  Available themes

  Vercel           vercel           0.5rem    Monochrome black/white

================================================================================
  12. RTL (RIGHT-TO-LEFT) SUPPORT
================================================================================

  Detection
  ──────────
  app/layout.tsx reads the Accept-Language HTTP header on every server
  render and calls detectDir():
    • Checks the first-preference language code against the RTL list:
        ar (Arabic), he (Hebrew), fa (Farsi/Persian), ur (Urdu),
        ps (Pashto), ku (Kurdish), sd (Sindhi), yi (Yiddish)
    • Returns "rtl" if matched, "ltr" otherwise.
  The result sets:
    <html dir="rtl|ltr" lang="ar|en">

  CSS utilities
  ─────────────
  • Tailwind logical properties used throughout:
      ms-auto  (margin-inline-start)   instead of ml-auto
      me-*     (margin-inline-end)     instead of mr-*
      ps-*     (padding-inline-start)  instead of pl-*
      pe-*     (padding-inline-end)    instead of pr-*
      border-e (border-inline-end)     instead of border-r
      text-start / text-end           instead of text-left / text-right
  • Directional icons carry data-dir-flip attribute.
    The CSS rule [dir="rtl"] [data-dir-flip] { transform: scaleX(-1) }
    automatically mirrors them in RTL mode.

  Special cases
  ─────────────
  • Phone number inputs always have dir="ltr" regardless of page
    direction, so phone digits are entered left-to-right.
  • VoterInfoForm: the phone <input> explicitly sets dir="ltr".
  • ExportPDFButton: icon uses ms-2 (RTL-safe logical margin).
  • DataTable: uses text-start / text-end for column headers and cells.

  2026-03-01  Recharts oklch colour fix (useChartColors hook)
  ─────────────────────────────────────────────────────────────
  • Recharts internally parses colour strings for hover effects,
    gradients, and animations. It cannot parse the oklch() colour
    function used by all five theme presets, producing the console
    error "Attempting to parse an unsupported color function 'oklch'".
  • Created hooks/useChartColors.ts: resolves CSS custom properties
    to rgb() strings by creating a hidden <span>, setting its CSS
    color to var(--X), appending it to <body>, reading
    getComputedStyle(el).color (which the browser converts to rgb()),
    then removing the element. Non-colour values (--radius) are read
    directly via getPropertyValue.
  • A MutationObserver on document.documentElement (watching the
    data-theme attribute and class attribute) re-resolves all colours
    whenever the theme or dark mode changes, keeping charts in sync
    with ThemeEditor live previews.
  • VoteBarChart, VotePieChart, TrendChart all updated to consume the
    hook and pass resolved rgb() strings to all Recharts colour props
    (stroke, fill, contentStyle, tick.fill, dot.fill).
